# v0.6.0-rc.1 — Validation and submission candidate

This candidate adds explicit fictional demo data, validation improvements, and reviewable capstone submission materials after the v0.5.0 administrator fee-management release.

## Delivered

- Administrator fee editing is available under **Club settings**. Conditional saves reject stale edits; future payments use the current fee while existing history and validity remain unchanged.
- An explicit seed command creates fictional membership/payment/event scenarios in `ClubOS-DB`. Reruns preserve records, timestamps, and passwords; startup never seeds/resets data.
- Both loopback development origins work with exact scheme/port checks; production retains exact origin matching.
- Mobile navigation supports focus containment, Escape, and focus restoration. Browser checks cover fee changes, keyboard access, mobile layouts, error recovery, and member restrictions.
- Compiled production smoke checks cover the complete account/payment/event/attendance workflow and secure cookie attributes, with scoped cleanup.
- CI includes browser acceptance and report/trace artifacts. README, screenshots, architecture, demo instructions, submission guide, and weekly devlog describe actual implemented behavior.

## Verification

- Clean `npm ci`, lint, TypeScript, 59 component/API tests, production builds, and compiled-server smoke checks passed locally.
- Six browser scenarios passed in installed Chrome and Firefox on disposable data.
- Documentation/image links and required README sections were checked.
- GitHub check results are available in [Actions](https://github.com/KNors22/club-os/actions/workflows/ci.yml).

## Pending final acceptance

This is a release candidate. No public application URL, live browser workflow, or real inbox delivery is claimed. Render and Atlas connections, private hosting settings, and Resend/demo-recipient configuration are still needed. Follow the [submission guide](../submission.md) and [deployment guide](../deployment.md), record actual live results, then publish the stable validation milestone.

QR cards/scanning, online payments, reports, announcements, scheduled reminders, multiple plans, administrator invitations, and password recovery remain outside the agreed MVP.
